## 3. 关键发现与处置

### 3.1 来源边界混淆（高）

**问题：** 工程六层栈曾被描述得像正典固定层次。正典只有元意义、结构意义、情境意义三个概念，并在 §8.1 重释为连续光谱带。

**处置：**

- 六层栈、三带、MSI 统一标注为 E0 工程扩展。
- 工程模块的 `anchor` 仅表示概念关联，不表示层定义来自正典。
- 在智能体、视频、白皮书和 Skill 中重复披露该边界。

**状态：** 已落实；后续任何新增文案必须通过一致性审计。

### 3.2 证据等级语义漂移（高）

**问题：** 旧发布页把 E3/E6 写成“观察证据”“跨文化外部验证”等不准确简称，可能造成证据虚高。

**处置：** 恢复 V7 定义：

| 等级 | V7.0 判据 |
|---|---|
| E0 | 构念已定义 |
| E1 | 已建立数学模型 |
| E2 | 存在测量工具，信效度验证中 |
| E3 | 存在预注册假设，数据收集中 |
| E4 | 独立实验室复现 |
| E5 | 已检验预注册证伪标准 |
| E6 | 跨情境、跨文化、跨时间泛化 |

**状态：** 发布页、文档和确定性智能体已按该定义修正；缺少项目内证据链的新主张保持 unknown/null，不自动授予实证等级。

### 3.3 失败矩阵混用（高）

**问题：** 工程六层失败矩阵与正典附录 D.7 五模块矩阵不一致，阈值与 MSI 配置也不一致。

**处置：**

- 正典附录 D.7：SG、Spectrum Spiral、Witness→Leap、MI-AI、Weaving Sovereignty。
- H1–H18：作为正典假设记录。
- 工程证伪草案：单列，并标记 `requires_preregistration=true`、`formal_disposition_allowed=false`。

**状态：** 已拆分表达，未修改正典阈值。

### 3.4 MSI 数字与实现不一致（中）

**问题：** 旧 README 声称“120 个粒子收敛为 12 个节点”，与配置不符。

**实际配置：** 过载计数 45、结构图 2 个节点、核心提炼 3 条、L3 示意 9 个点。

**状态：** 仓库文档已按实现修正；发布视频使用实测时间轴。

- 在相关段落加入编辑说明。
- 增加 V7 E0–E6、来源哈希、上游缺陷、六层工程边界、2026 实施产物、变更日志和参考文献附录。

### 3.7 发布页可重复构建缺陷（中）

**问题：** 手工修复会被两个构建器覆盖；存在旧证据标签、视频 poster 指向 MP4、重复 `cpBtn` ID、不准确的“18 幅书稿原版插图”表述。

**处置：**

- 新增确定性后处理 `meaning-intelligence-publish/scripts/finalize_publish.py`。
- 两个发布构建器均在生成后调用后处理。
- 修正标签、封面、ID、中英核心说明和项目示意图表述。
- 下载、项目说明书和 MCP 导航仅在目标文件存在时注入。

**状态：** 已实施；最终目标文件齐备后已再次运行后处理，并通过发布包结构验收。

### 3.8 验收脚本覆盖不足（高）

**问题：** 旧校验只检查核心文件存在，不能证明 EPUB、媒体、下载清单、完整 ZIP 或 Web MCP 满足要求。

**处置：**

- `verify_package.py` 增加 HTML/JS、重复 ID、本地引用、字幕时间轴、EPUB 容器/OPF/spine/XHTML、Office 结构、媒体流/时长/音量、manifest 安全路径/字节数/SHA-256、完整 ZIP 和 V7 标签检查。
- `verify_site.py` 增加全部 manifest 资源 HEAD 检查、可选全量哈希、页面内容检查、CORS、认证 initialize、tools/resources 与只读 analyze 检查。
- 在线令牌只从 `MI_MCP_PUBLIC_TOKEN` 环境变量读取，不输出。

**状态：** 扩展验收已执行；发布包通过结构、媒体、Office、EPUB、manifest、完整 ZIP 与 Pages Function 适配器检查。部署 ZIP 按 staging 文件集合逐文件核对名称、字节数和 SHA-256，不再误用完整包文件集合。

### 3.9 智能体 schema 与安全边界（高）

**处置：**

- 六个注册技能严格按 L1–L6 顺序。
- 离线模式仅用 Python 标准库，结果确定性可复现。
- 可选 LLM 仅提供未核验写作建议，不能改变证据、尺度聚合或批准状态。
- Web 与 HTTP MCP 只绑定 `127.0.0.1`；公开 Pages Function 使用独立强令牌。
- 人类批准默认 pending；反馈修订使失效批准回到待定。
- 无任意文件读取、命令执行、代码执行或输入驱动的网络访问。

**状态：** 核心实现通过 127 项单元测试、编译检查、Node 语法检查和 CLI/API/MCP 冒烟测试；本地浏览器已检查中英切换、离线模式与外部动作默认 pending 的人工批准边界。Web MCP 24 项测试通过，其中新增 Pages Function `onRequest` 适配器测试；这些检查不替代生产环境浏览器验收。

### 3.10 Git 行尾归一化（低）

**现象：** 仓库 `core.autocrlf=true`，`.gitattributes` 要求 LF，导致大量一次性的整文件差异。

**处置：** 保留既有 `.gitattributes`，不修改 Git 配置，不通过 reset/clean 掩盖差异；提交前仅纳入已验收文件并检查 staged diff。
