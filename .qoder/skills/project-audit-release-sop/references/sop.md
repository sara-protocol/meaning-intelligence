# 通用项目审查与发布 SOP

本手册是 `project-audit-release-sop` 的执行层。所有占位符必须在开始时替换；未知项保持未知。

## 阶段总表

| 阶段 | 输入 | 核心动作 | 输出 | 通过门 | 回滚/停止条件 |
|---|---|---|---|---|---|
| P00 配置 | 用户需求、现有资料 | 明确目标、授权、权威来源、变量 | 项目配置卡 | 每个必需变量有值或明确 unknown | 关键范围不清时停止外部动作 |
| P01 来源 | 正典、需求、设计、数据 | 排优先级，标只读与可衍生 | 来源登记表 | 冲突有记录，不改原件 | 权威来源缺失时停止内容定稿 |
| P02 基线 | 仓库、包、日志 | 记录提交、状态、哈希、依赖、命令 | 基线快照 | 工作树状态可解释 | 不清理陌生未提交文件 |
| P03 并行审查 | 基线、范围 | 分领域只读审查 | 发现清单 | 每项有证据与范围 | 不扩大子代理权限 |
| P04 反思排序 | 发现清单 | 归类、证据分级、排优先级 | 反思与修复计划 | 每项绑定验收门 | 不把未知当已解决 |
| P05 修复 | 计划、来源 | 改生成器/源代码，重建产物 | 变更集 | 受影响测试通过 | 保留可恢复基线 |
| P06 本地验收 | 变更集 | 测试、浏览器、媒体、包、文档 | 本地验收报告 | 所有必需门通过 | 失败即停止发布 |
| P07 人工门 | 报告、具名交付物 | 内容、权利、无障碍、安全等评审 | 批准/待办记录 | 必需人工项明确批准 | pending 不等于 approved |
| P08 发布前 | staged diff、授权 | 审文件、秘密、版本、链接、回滚点 | 发布清单 | 范围与授权一致 | 无授权则不发布 |
| P09 发布 | 发布清单 | 非强制发布并记录标识 | 发布回执 | 远端标识可追踪 | 用已准备的回滚方案 |
| P10 在线验收 | 公网 URL | 重跑关键功能、媒体、下载、API | 在线验收报告 | 实际线上行为符合目标 | 不用本地结果代替 |
| P11 复盘 | 全部证据 | 比较目标与结果，提炼经验 | 复盘记录、SOP 修订 | 偏差与待办可见 | 未完成项保持打开 |

## P00–P02：配置、来源与基线

### 项目配置卡

- 目标：写清用户要达成的最终状态，不把已完成子集当目标。
- 范围：列入具名文件、页面、命令、服务、语言、格式和渠道。
- 授权：逐项列出可读、可改、可构建、可提交、可推送、可部署、可修改配置。
- 人工门：列出必须由人判断的项目。
- 验收：每项需求映射到证据，不只列测试名。

### 来源登记表

| 来源 | 角色 | 权威优先级 | 只读? | 哈希/版本 | 冲突处理 |
|---|---|---:|---|---|---|
| `<SOURCE>` | 正典/需求/设计/数据/生成物 | `<N>` | 是/否 | `<HASH>` | 记录，不静默覆盖 |

规则：

1. 生成物不能反过来覆盖权威来源。
2. 用户原件默认只读；补充材料单独版本化。
3. 版本号、日期、计数必须来自单一来源或交叉验证。
4. 证据等级、实验状态和营销表述分开。

### 基线快照

记录：

- 当前分支、HEAD、工作树状态。
- 关键文件字节数和 SHA-256。
- 依赖版本和运行环境。
- 当前清单成员数、总字节数、最大单文件。
- 当前站点/服务标识和公开状态。
- 未提交改动的归属；不 stash、restore、clean 陌生工作。

## P03：并行审查

### 分工原则

- 每个领域有互斥范围，避免多个代理重复搜索。
- 审查代理默认只读；不安装依赖、不部署、不提交、不读凭据。
- 提示词写明“报告事实而非修改”，并要求绝对路径、行号、JSON 键或命令输出。
- 主代理负责交叉核对和去重，不把子代理结论直接当事实。
- 大型文件读取使用窗口；不要用 shell 输出完整日志或二进制。

### 发现记录

每条发现包含：

```text
ID、领域、严重度、状态（confirmed/inferred/unknown）
用户影响
证据（文件:行、命令、URL、哈希）
根因假设
修复范围
验收命令与预期
是否需要人工门
```

严重度：

- `blocker`：安全、数据丢失、核心交付不可用、未授权发布。
- `high`：主要功能或一致性错误。
- `medium`：可恢复性、维护性或边缘路径缺陷。
- `low`：不影响正确性的改进。

## P04：反思与修复计划

反思不是重复问题清单，必须形成可复用决策：

- 保留：有证据证明有效的做法。
- 修正：导致错误或返工的做法。
- 自动化：高重复、确定性、易漂移步骤。
- 人工保留：权利、语气、可访问性、科学结论等判断。
- 未知：需要新证据，不能靠解释消除。

每项修复写清：

```text
问题 → 根因 → 最小完整修复 → 影响文件 → 重建步骤 → 验收证据 → 回滚点
```

## P05–P06：修复与本地验收

### 修改规则

- 优先改来源和生成器，不手改可再生成文件。
- 不顺手重构无关代码。
- 不为不可能发生的内部场景增加防御；在用户输入、外部 API 和发布边界做验证。
- 新功能必须与测试一起交付；测试要覆盖实际生产路径。
- 媒体、文档、哈希和清单是一个变更单元。

### 验收顺序

1. 语法/类型/构建。
2. 单元与集成测试。
3. 真实运行路径与失败路径。
4. 浏览器 golden path、语言切换、移动端、下载、媒体播放。
5. 文档结构、PDF 渲染、字幕同步、媒体时长与解码。
6. 包清单、成员安全、字节数、SHA-256、自排除。
7. 部署 staging 与目标平台能力差异。
8. 人工门。

验证器配置规则：

- 不把项目路径、正式域名、版本、文件数、哈希或提交写死在代码里；从参数、环境配置、当前 manifest 和实时 Git 读取。
- 每个 HTTP 请求、CDP 调用和子进程都有明确超时；429/5xx 使用有界退避，不无限重试。
- 为每个发布平台记录能力：静态文件、Function、Range、Access、缓存、构建触发、回滚方式。
- Access 登录凭据与 API/MCP 业务凭据分开；临时令牌不进入命令行、日志、文档或提交。
- 音频、视频、图片和压缩包在 Git 属性中显式标记二进制；是否使用 LFS 由仓库策略决定。

### 跨项目强制验收门

- **部署身份**：CI 直接比较权威源与真实部署入口文件字节；临时目录测试只验证工具，不替代部署物校验。
- **滥用边界**：限流、请求大小、并发和成本控制覆盖未认证流量；分别测试合法、错误凭据和超限请求。
- **契约登记**：每个 API/MCP 记录协议版本、资源/工具集合、参数与错误语义；同名不同契约不得混用。
- **媒体实测**：用解码器读取实际时长，检查字幕末点、章节点和播放器元数据；不得使用合成脚本的估计时长替代。
- **副本一致性**：源 PPT、发布 PPT、二维码、页面、文档和下载副本使用同一正式入口；二进制逐字节比较，二维码实际解码。
- **严格完成**：提供 `--strict` 或等价模式；任一必需检查 skipped/blocked/pending-human 时退出非零且禁止“全部通过”。
- **秘密边界**：忽略本地环境文件与工具状态目录；CI 检查凭据文件名和暂存内容，不读取或输出值。

### 长任务与可恢复验证

- 长时间下载或全量哈希不要每次从零开始。
- 每完成一个文件就持久化 `path/bytes/sha256/status`。
- 使用有界并发和逐文件超时；用完成即写，而非等待全部结束。
- 超时任务保留部分结果；重启只处理 pending。
- 全量完整性只有在全部必需成员通过后才能标 `true`。
- 包内自引用字节数应放外部清单，避免压缩不动点。

### 证据状态

只使用：

- `pass`：实际执行且符合预期。
- `fail`：实际执行且不符合预期。
- `skipped`：明确未执行，附原因。
- `blocked`：外部条件缺失，附解除条件。
- `pending-human`：自动检查完成，等待人的判断。

## P07–P08：人工门与发布前

### 人工门清单

按项目选择，不默认全部需要：

- 内容准确性与正典边界。
- 版权、商标、字体、音乐、图片和人物权利。
- 中文/英文语气与 pronunciation。
- 无障碍：键盘、焦点、对比度、字幕、替代文本。
- 安全：鉴权、权限、秘密、数据边界。
- 科学或实证结论：独立评审、预注册、复现。
- 最终视觉与品牌接受。

人工批准记录必须包含具名评审项、材料版本/哈希、决定、时间与评审方式。`pending-human`、沉默、自动检查全绿都不是批准。

### 发布前检查

- staged diff 与需求一致，无陌生文件。
- 无 `.env`、凭据、token、临时下载、`.uploading.cfg`、缓存。
- 大文件走平台允许的机制；不绕过大小限制。
- 换行、二进制和重命名规则不会改变媒体或确定性文本。
- 发布目标、分支、目录、构建类型与用户授权一致。
- 域名、二维码、页面、PPT、文档、下载和清单使用同一正式入口。
- 记录发布前 HEAD、包哈希和回滚目标。

## P09–P10：发布与在线验收

### 发布

- 先普通推送/发布，失败时诊断；不使用强推绕过。
- 记录提交、部署 ID、构建 ID、时间和发布者。
- 若平台有 Access、审批或审批门，公网 302 不能写成功能通过。
- 修改共享权限、DNS、Access 或新公共表面需要单独授权。

### 在线验收

从公网验证，而不是依赖本地文件：

- HTTPS、首页、关键深层链接、404。
- 中英切换、移动端、键盘和主要交互。
- 下载链接的 HEAD/GET、Content-Type、长度和哈希。
- 音频/视频可播放、时长正确、字幕轨存在。
- Range 支持按平台实测；静态 Pages 返回 200 不等于流式服务通过。
- API/MCP 的协议、鉴权、资源、工具、错误与限流。
- CDN 缓存导致的旧内容；用版本化文件名或受控刷新。

## P11：复盘

输出三张短表：

1. 目标与证据：每项需求对应结果。
2. 偏差与待办：未完成、弱验证、人工 pending。
3. 可复用经验：规则、检查门、脚本、提示词。

只有当全部明确需求都有充分证据且无必需人工门阻塞时，才可声明项目完成。测试全绿、清单完整或投入时间长都不是单独完成证明。

## 回滚原则

- 发布前保留可识别回滚点和包哈希。
- 优先前滚修复；回滚必须已知影响且获授权。
- 数据库或共享配置回滚单独评估，不与代码回滚混为一谈。
- 回滚后重新执行在线验收，并记录用户可见影响。
