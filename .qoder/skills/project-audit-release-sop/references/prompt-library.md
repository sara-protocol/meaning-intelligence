# 阶段提示词备用元件

复制相应提示词，替换 `<...>`。提示词中的权限约束必须保留。可将 P03-a 至 P03-d 并行发给不同只读代理。

## P00：建立项目配置

```text
你是项目交付主代理。目标：<OBJECTIVE>。
项目根：<PROJECT_ROOT>。已有资料：<INPUTS>。
先只读建立项目配置卡：权威来源、具名交付物、版本来源、构建/测试命令、发布目标、禁止动作、人工门、证据目录。
每项标 confirmed / inferred / unknown。不得猜测 URL、版本、授权或测试结果。
当前授权仅限：<AUTHORIZED_ACTIONS>。未列出的 commit/push/部署/删除/共享配置修改一律不执行。
输出：需求到证据 checklist、缺失信息、建议的并行审查范围。
```

## P01：来源与正典边界

```text
只读审查来源结构，不修改任何文件。
根目录：<PROJECT_ROOT>。候选权威来源：<AUTHORITATIVE_SOURCES>。
确定优先级、只读原件、可衍生文件、版本唯一来源和冲突处理方式。
核对哈希或版本证据，引用绝对路径与行号。
输出来源登记表；冲突单独记录，不静默修复正典或用户原件。
```

## P02：基线快照

```text
只读捕获当前基线：分支、HEAD、工作树状态、关键交付物字节数/SHA-256、依赖版本、现有 manifest、最近测试日志、当前公开站点/部署标识。
根目录：<PROJECT_ROOT>。证据输出到 <EVIDENCE_DIR>/baseline。
不清理、不 stash、不 restore 陌生改动，不读取凭据。
输出机器可读基线 JSON 和简短异常列表。
```

## P03-a：交付物一致性审查

```text
你是只读交付审查代理，不修改、不构建、不发布。
范围：<DELIVERABLES> 及其 manifest、文档、下载页、媒体、字幕、二维码、域名。
逐项核对版本、计数、链接、语言切换、时长、格式、哈希和包边界。
每项发现引用绝对路径:行号、JSON 键或可复现命令；区分 confirmed/inferred/unknown。
不要审查源代码内部实现。用中文，500 字以内，输出 blocker/high/medium/low、证据、修复范围、验收门。
```

## P03-b：工程与安全审查

```text
你是只读工程审查代理，不修改、不安装依赖、不部署、不读 token。
范围：<CODE_PATHS>、<TEST_PATHS>、<CI_PATHS>。
检查真实运行路径、构建与测试覆盖、输入边界、鉴权、CORS、限流、请求上限、错误泄露、秘密处理、确定性和失败行为。
限流必须覆盖未认证请求；CI 必须直接校验真实部署文件与权威源字节一致；分别登记同名 API/MCP 的协议、参数和错误契约。
可运行已有测试；记录命令与结果。不要审查发布包媒体和域名一致性。
输出确认问题、未验证风险、证据位置和工程验收门，中文 500 字以内。
```

## P03-c：发布运维审查

```text
你是只读发布运维审查代理，不修改、不外部写操作、不读凭据。
范围：<RELEASE_SCRIPTS>、<GIT_CONFIG>、<DEPLOY_CONFIG>、<ONLINE_VERIFIERS>。
检查陈旧硬编码、超时与恢复、换行/二进制/重命名风险、平台能力差异、回滚、秘密边界、人工审批门和可迁移性。
验证器必须从参数、当前 manifest 和实时 Git 读取项目事实，不写死域名、版本、计数、哈希或提交；网络与子进程必须有超时。
引用绝对路径:行号或脚本名。输出阶段 SOP、主要风险和回滚建议，中文 500 字以内。
```

## P03-d：内容、体验与权利审查

```text
你是只读内容与体验审查代理，不修改、不发布。
范围：<CONTENT_PATHS>、<UI_PATHS>、<MEDIA_PATHS>。
检查权威来源边界、证据标签、版本表述、中英质量、pronunciation、字幕、无障碍、移动端、版权/字体/图片/音乐权利和人工接受门。
自动检查与人工判断分开；未知权利状态不得写成已授权。
输出证据、人工待办和通过门，中文 500 字以内。
```

## P04：反思与修复计划

```text
汇总以下只读审查结果：<FINDINGS>。
不要重复搜索。按正确性、一致性、安全性、可维护性、可恢复性、用户体验、权利与证据归类。
区分 confirmed/inferred/unknown，按影响×证据强度×成本排序。
回答：哪些做法有效、哪些绿色检查覆盖不足、哪些步骤应自动化、哪些必须人工保留、下次应在哪个更早门失败。
输出最小完整修复计划；每项绑定文件范围、验收命令、预期证据和回滚点。
```

## P05：实施修复

```text
按批准计划实施：<APPROVED_PLAN>。
只改所列范围；优先改来源和生成器，不手改可再生成产物。
不得 commit/push/部署，除非计划明确包含相应授权。
每项修复后运行绑定验收；失败保留日志并修根因，不降低标准或改校验器绕过。
输出变更文件、生成物、命令结果和未解决项。
```

## P06：独立本地验收

```text
独立验证变更集 <CHANGESET>，不假设实施者结论正确。
从干净可解释状态运行 <BUILD_AND_TEST_COMMANDS>，再做真实浏览器、文档/媒体解码、下载和包完整性检查。
用实际编码时长核对字幕末点和章节时间；核对源文件与发布副本字节及二维码内容；检查真实部署入口而非临时副本。
记录 pass/fail/skipped/blocked/pending-human；跳过必须说明原因，严格模式不得把跳过当通过。
重点寻找测试未覆盖的生产路径。输出逐项证据和是否允许进入发布前门。
```

## P07：人工评审门

```text
准备人工评审包：<REVIEW_ARTIFACTS>。
列出需要人判断的内容准确性、权利、pronunciation、无障碍、安全、视觉和 Empirical 结论。
每项给出预览/路径、自动检查结果、风险、建议决定。
记录评审项、材料版本/哈希、决定、时间与评审方式；不得把 pending-human 视为 approved；未批准项保持阻塞。
```

## P08：发布前审计

```text
发布前只读审计。授权目标与动作：<RELEASE_AUTHORIZATION>。
检查 staged diff、秘密、临时文件、版本、正式入口、二维码、下载、媒体、清单、构建配置和回滚点。
核对实际部署入口与权威源字节一致；核对源 PPT/发布 PPT 的二维码和媒体时间轴；不得用临时副本校验替代部署物校验。
核对当前 HEAD 与包哈希。任何范围外文件或秘密立即停止。
输出发布清单、阻断项和建议 commit message；此时不执行发布。
```

## P09：执行发布

```text
在以下明确授权范围内发布：<RELEASE_AUTHORIZATION>。
发布前基线：<BASELINE>；包哈希：<ARTIFACT_HASH>；回滚点：<ROLLBACK_TARGET>。
使用非强制、可追踪方式；失败先诊断，不强推、不跳 hook、不改共享权限。
记录 commit/build/deployment ID、时间、目标和结果。失败时按已批准回滚方案处理。
```

## P10：在线验收

```text
从公网验收 <PUBLIC_URLS>，对应发布标识 <RELEASE_ID>。
重新验证 HTTPS、首页、深层链接、中英切换、移动端、主要交互、下载 GET/HEAD、哈希、媒体播放/时长/字幕、API/MCP 和缓存。
按目标平台实测 Range、Function、Access 行为；记录实际状态码和限制。
长任务逐文件持久化结果，超时保留部分证据，重启只处理 pending。
输出在线报告；未通过项不得用本地通过替代。
```

## P11：事件与回滚

```text
处理发布事件 <INCIDENT>。当前影响：<IMPACT>；授权回滚范围：<ROLLBACK_AUTHORIZATION>。
先观察公网状态和日志，定位根因；比较前滚修复与回滚的影响。
未获授权不执行破坏性回滚或共享配置修改。
执行后重新跑在线验收，记录用户可见影响、恢复标识和后续防复发门。
```

## P12：复盘与 SOP 更新

```text
基于目标、基线、发现、修复、本地/在线证据和人工评审做完成审计：<EVIDENCE_BUNDLE>。
建立提示词到交付物 checklist；每项标 pass/fail/skipped/blocked/pending-human 并引用证据。
识别缺失、弱验证和未覆盖需求；只有全部明确需求满足且无必需人工阻塞时才可声明完成。
把可泛化经验提炼为规则/检查门/提示词；项目专属事实留在项目 reference。
输出复盘、剩余待办和 Skill 修订建议。
```

## P13：迁移到同类项目

```text
将本 SOP 迁移到新项目 <NEW_PROJECT_ROOT>，保留流程与证据规范，移除旧项目路径、域名、版本和结论。
重新建立项目配置卡、来源登记表和基线；逐项替换提示词占位符。
先在小范围只读试用 P03 并行审查，再按实际项目删减不适用阶段。
输出迁移差异、缺失项目命令和需要人工确认的授权/人工门。
```

## P14：生成项目总结

```text
根据 <FINDINGS>、<TEST_EVIDENCE>、<RELEASE_EVIDENCE> 生成项目审视反思总结。
结构：目标与范围、已完成与证据、确认问题、推断风险、未知/人工待办、关键教训、下一步。
事实与建议分开；不使用“全部完成”覆盖 blocked 或 pending-human。
引用路径、命令、哈希和发布标识，控制在 <WORD_LIMIT> 字。
```

## P15：维护提示词库

```text
审查现有提示词 <PROMPT_LIBRARY> 是否覆盖 intake、来源、基线、并行审查、反思、修复、本地验收、人工门、发布前、发布、在线验收、回滚、复盘和迁移。
检查每条是否包含范围、权限、证据格式和停止条件。
只补缺口，不重复段落；输出新增/修订提示词及理由。
```

## P16：Skill 自校验

```text
校验 Skill 目录 <SKILL_DIR>：frontmatter、名称、单行 description、正文行数、UTF-8、资源存在、无缓存/临时文件、提示词阶段覆盖。
运行 <SKILL_DIR>/scripts/validate_skill.py，记录实际输出。
结构通过不代表项目验收通过；分别报告两层结果。
```
