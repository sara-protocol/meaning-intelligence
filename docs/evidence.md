# 证据体系 / The Evidence System

> 这份文档回答一个问题：**说某一层是「E1」到底意味着什么，以及这个标注为什么不能当作质量评分来读？**
> This document answers one question: **what does it actually mean to label a layer "E1", and why must that label not be read as a quality score?**

---

## 一、E0–E6：七级定义 / E0–E6: Seven Levels

证据等级回答的不是「这个想法好不好」，而是**「关于它，我们目前知道了什么」**。级别越高，表示它
经历过的检验越多、越独立；级别低**不构成**缺陷指控，只表示检验尚未发生。

An evidence level does not answer "is this a good idea" but **"what do we currently know about it"**.
A low level is **not** an accusation of weakness; it means the test has not happened yet.

| 等级 | 名称 / Name | 含义 / Meaning |
|---|---|---|
| **E0** | 概念 / Conceptual | 构念已定义、术语可用，但尚无形式化表述。 / The construct is defined and the term usable, but nothing is formalized. |
| **E1** | 形式化 / Formalized | 已有明确表述（方程、结构、判定规则），可推导可讨论，但尚无可操作指标。 / Stated explicitly, so it can be reasoned about, but not yet operationalized. |
| **E2** | 操作化 / Operationalized | 已有测量程序或工具：指标、计分、单位明确，别人可以照着做一遍。 / A procedure or instrument exists, explicit enough for someone else to repeat. |
| **E3** | 预测性 / Predictive | 在**新**数据上给出了方向与量级正确的预测。 / Predicted direction and magnitude correctly on **new** data. |
| **E4** | 复制 / Replicated | 预测在**独立**数据或独立团队处再次成立。 / Held again on independent data or by an independent group. |
| **E5** | 证伪或存活 / Falsified or Survived | 已被认真尝试证伪：或达到预注册标准而失败，或通过了预先声明的检验仍未被推翻。 / Serious falsification attempted: the preregistered criterion was met and the claim failed, or it survived a pre-declared test. |
| **E6** | 外部验证 / Externally Validated | 由本框架之外的领域独立确认，且不依赖本框架的术语与工具。 / Independently confirmed by fields outside this framework. |

两个容易读错的地方：

- **E5 是双出口。** 它既包括「被证伪」，也包括「经检验而存活」。被标为 E5 且已证伪是一项**成果**，
  不是丑闻——它意味着这条主张曾经足够具体，具体到可以被推翻。
  **E5 has two exits.** A claim marked E5-and-falsified is a **result**, not a scandal: it means the claim was specific enough to be refuted.
- **E4 不是「更可信的 E3」。** 它要求的是**独立性**：新的数据、或换一批人来做。同一团队在同一样本上
  再做一遍，不构成 E4。
  **E4 is not "a more convincing E3".** It demands **independence**; re-running the same analysis on the same sample by the same team does not reach E4.

## 三、为什么必须区分这两个等级 / Why the Two Levels Must Be Kept Apart

「L1 减负是 E1」这句话**单独说是误导性的**，因为它会让人误以为「减负这件事没有证据」。事实正相反：
认知负荷与受控语言有长期的实证积累。真正没有证据的是**别的**东西——把它们按这一层的方式打包起来、
在这个框架里使用，是否真的产生声称的效果。

Saying "L1 is E1" **on its own is misleading**, because it suggests load reduction has no evidence
behind it. The opposite is true: cognitive load and controlled language have a long empirical record.
What lacks evidence is something else — whether packaging them this way, inside this framework,
actually produces the claimed effect.

| 问题 Question | 由哪一列回答 Column |
|---|---|
| 「压缩信息真的能降低认知负荷吗？」<br>"Does compressing information actually reduce cognitive load?" | **底层机制**：有大量独立研究，E3–E4。<br>**Underlying mechanism**: much independent work, E3–E4. |
| 「L1 这一层（300 字硬上限＋受控语言＋两份清单）作为一个整体，是否真的提升了决策质量？」<br>"Does L1 *as a package* — hard word limit plus controlled language plus the two lists — actually improve decision quality?" | **本框架内的操作化**：尚无检验，E1。<br>**Operationalization in this framework**: untested, E1. |

这两件事的差别不是措辞问题。一个机制的成熟**不能**转移给使用它的那一层：如果 L1 的组合方式选错了
（例如压缩掉了边界信息），底层机制的成熟度无法阻止它的失败。反过来，把两者混为一谈也会造成另一种
错误——用「机制很成熟」来为「本层有效」背书。

The distinction is not a matter of phrasing. The maturity of a mechanism **cannot** be transferred to
the layer that uses it: if L1 packages the mechanism badly (say, compressing away boundary
information), the mechanism's maturity will not save it. Conflating the two causes the opposite error
as well — using "the mechanism is well established" to endorse "this layer works".

**同样的区分适用于另外两层。** L2 的多媒体学习与双通道效应（机制 E3）不能证明「每个概念做一个可交互
产物」这条操作规则有效（本框架 E1）。L6 的案例支持（E2）说明「归零缓解僵化」有案例层面的痕迹，
但 RCT 仍在进行，因此不能读作因果确认。

**The same distinction applies to other layers.** Multimedia learning and dual-channel effects
(mechanism E3) do not establish that "one interactive artifact per concept" works (framework E1). The
case support behind L6 (E2) shows traces of "zeroing relieves ossification" at the case level, but the
RCT is still running, so it cannot be read as causal confirmation.

> **各处引用本项目时，请标明你说的是哪一列。** 只写「L1 = E1」会丢失这条区分，并让一项其实有扎实
> 机制基础的做法看起来比实际更弱。
>
> **When citing this project, say which column you mean.** Writing only "L1 = E1" loses the distinction
> and makes a practice with a solid mechanistic basis look weaker than it is.

## 四、六层栈本身是 E0 / The Stack Itself Is E0

> **六层栈是一个整合结构，证据等级 E0（概念），尚未经过独立检验。**

这一点没有例外条款：

- `config.json` 把它数据化、动画把它可视化、页面让它可操作——**这些都不提高它的证据等级**。
  工程实现改变的是它**可被体验**的程度，不是它**已被检验**的程度。
  Encoding it in `config.json`, animating it, and making it operable **do not raise its evidence level**.
- 它的分层方式**可能不是最优切分**。若出现更简洁且解释力更强的切分，应当**替换**它，而不是为它辩护。
  Its partition **may not be the optimal cut**; a simpler partition with greater explanatory power should **replace** it rather than be defended.
- 因此六层应被当作一个**待检验的组织工具**，而不是一个已证实的发现。
  Treat it as a **testable organizing tool**, not a confirmed finding.

这也解释了为什么 [`failure-matrix.md`](failure-matrix.md) 里每一层都带失败阈值：如果整合结构的切分错了，
错误会先在**某一层**的失败上显形，而不是以「整个框架崩溃」的方式出现。

This is also why every layer in the failure matrix carries a failure threshold: if the partition is
wrong, the error surfaces first as **one layer failing**, not as the whole framework collapsing.

## 五、证据等级不是质量评价 / An Evidence Level Is Not a Quality Judgment

这一节是使用本体系的**前置条件**，不是补充说明。

This section is a **precondition** for using the system, not an afterthought.

| 常见误读 Misreading | 实际含义 What it actually means |
|---|---|
| 「E0 等于没用。」 | E0 表示构念已定义、尚无可检验表述。**定义清楚本身就是进展**，但它是 E0 的进展，不是 E3 的。 |
| 「E2 比 E1 好，所以应该尽快升级。」 | 等级描述**知识状态**，不是进度条。为升等级而放宽标准（HARKing）恰好是被 [CONTRIBUTING.md](../CONTRIBUTING.md) 明确拒绝的行为。 |
| 「机制是 E4，所以这一层是 E4。」 | 见第三节。机制与使用它的层是**两个**不同的主张。 |
| 「等级低就先别公开。」 | 恰好相反：本项目的做法是**低等级照实公开**，并附上什么观察会让它作废。 |
| 「E5 是最高级之一，说明很可靠。」 | E5 包含「已证伪」这一出口。它衡量的是**检验的严肃程度**，不是主张的正确程度。 |

一句话概括：**证据等级是知识状态的标注，不是主张的质量评分。** 它告诉你这条主张走过了哪些检验、
还差哪些检验，而不是告诉你该不该相信它。相信与否由读者根据标注自行决定——这正是标注存在的理由。

In one line: **an evidence level is an annotation of knowledge state, not a quality score for a
claim.** It tells you which tests a claim has passed and which are outstanding, not whether you should
believe it. That decision stays with the reader — which is precisely why the annotation exists.
